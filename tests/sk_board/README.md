# SK 控制板 V1.0：ESP-IDF 板测程序

独立项目，目标 ESP32-C3FH4，ESP-IDF **5.2.3**，固件版本 **0.1.1-sk-test**。通电表示解锁；用户规定最长 **1 秒**。默认构建已**开放低有效锁输出**，用于人工台架测试。不会在启动、按键、电量低或 Wi-Fi 扫描时自动开锁。

首次试锁：开机等至少10秒，在115200串口逐行发送 `arm`、`pulse 100`（每行回车），执行一次100ms脉冲。再次测试需等断电后10秒并重新 `arm`。`off` 可随时请求关断；电池校准失败或电压不在3300～4250mV时仍会拒绝动作。

## 原样实板的电路注意点

1. **M1 栅极与 GPIO3 隔离/电平转换**：R2 把栅极拉到电池电压，满电约 4.2V，直接接 ESP32 不合适；输出 3.3V 也不能保证 M1 关断。高阻/开漏输出不能解决引脚过压。应增加适当栅极驱动，并确保复位、下载、MCU 断电时线圈保持断电。
2. **线圈续流/钳位**：图中未见。按实际线圈电流和释放速度选择二极管/TVS 等器件；普通续流二极管会延长电流衰减。M1 型号、额定电流、线圈额定电压也须核对。
3. **Q1 基极限流**：GPIO1 与 Q1 基极之间未画串联电阻。默认只以内部弱上拉尝试保持供电，避免直接强驱基极；这不等于已验证能可靠自保持。加入合适基极电阻后可切换推挽保持。

**开放软件输出不代表这些电路问题已解决，也不代表GPIO关断后线圈一定断电。** 建议先以假负载测量关断电压/电流；实测时保持可直接切断电池供电。本固件没有在该实板上运行过。

J2 的供电是 **VCC_BAT**，不是 USB 5V：此单节锂电充电电路满电约 4.2V，随电池放电下降，负载时还会有压降。不能由此推断线圈额定电压就是 4.2V。

## 引脚和测量范围

| 功能 | GPIO/通道 | 实现 |
|---|---|---|
| 电池电压 | GPIO0 / ADC1_CH0 | 12 bit、12dB、eFuse 曲线校准，R4/R7=10k/10k，电池电压=采样电压×2 |
| 供电自保持 | GPIO1 | 默认开漏释放+内部上拉；关机时拉低 |
| K5 电源键 | GPIO2 / ADC1_CH2 | 按下约 VBAT/2，400/800mV 回差；去抖30ms |
| 电磁锁 | GPIO3 | 原图低有效；修正驱动后的有效极性可配置 |
| 蓝色 D3 | GPIO4 | 高有效；启动闪3次，串口可点亮/熄灭/闪烁 |
| K3 / K4 | GPIO8 / GPIO10 | 外部上拉、低有效；输出事件和次数，不触发锁 |
| K1 BOOT | GPIO9 | 运行时只检测按键；复位时承担下载选择 |
| K2 RESET | CHIP_EN | 不能被 GPIO 读取；通过重启日志/复位原因检查 |
| USB | GPIO18 D- / GPIO19 D+ | 默认命令输入和日志输出 |
| UART0 | GPIO21 TX / GPIO20 RX | 可单独构建为主控制台，3.3V UART、115200 8N1 |

每20ms读取按键和两路ADC，每通道丢弃一次切换后的读数后平均8次，每秒打印一次。原始值、批次最小/最大值、校准mV及电池mV同时打印。校准或采样失败不会伪造电压，锁授权被拒绝。3300～4250mV 是本测试程序允许动作的电池窗口，不是测得的线圈规格或电池保护参数，不估算电量百分比。

## 编译与烧录

在本目录执行（当前工作目录的完整路径见交付消息）：

```powershell
. C:\Users\46907\esp\v5.2.3\esp-idf\export.ps1
idf.py build
# COMxx 替换为确认属于这块新板的端口
idf.py -p COMxx flash monitor
```

默认 target 已固定为 esp32c3。原生 USB 控制台，终端选 115200 8N1，命令以回车或换行结束。按 Ctrl+] 退出 IDF monitor。首刷若无法进入下载模式：保持电源键供电，按住 BOOT，按一下 RESET，再松 BOOT；普通启动不要按 K3/BOOT（GPIO8/9 为绑带引脚）。本图 USB 5V 接充电芯片，不是直接送至 LDO 输入；USB 枚举和 MCU 供电还依赖电池/供电自保持，需实际检查。

使用 UART0 时单独建目录和配置，避免串口选项污染默认 USB 产物：

```powershell
idf.py -B build-uart -D SDKCONFIG=sdkconfig.uart -D "SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.defaults.uart" build
idf.py -B build-uart -D SDKCONFIG=sdkconfig.uart -p COMxx flash monitor
```

USB-TTL 必须为3.3V电平，适配器 RX 接板 TX0、TX 接板 RX0、GND 共地，不能将适配器5V逻辑接 MCU。

## 串口命令

| 命令 | 功能 |
|---|---|
| `help` / `status` | 帮助 / 立即输出电压、按键、温度、内存与锁状态 |
| `selftest` | 先请求断锁并取消授权；检查身份、MAC、Flash大小、应用SHA256读取、堆完整性和独立NVS命名空间读写恢复 |
| `led on` / `led off` / `led test` | 点亮 / 熄灭 / 闪3次，需观察真实D3 |
| `wifi` | 异步被动扫描，输出AP数量、信道与RSSI；不连接网络、不保存凭据；扫描前断锁并禁止扫描中授权 |
| `arm` | 授权下一次脉冲，30秒过期；构建配置禁用、电压异常、故障、冷却或正在动作时拒绝 |
| `pulse` / `pulse 100` | 默认100ms；允许20～1000ms，单次执行后必须重新授权 |
| `off` | 立即请求断锁并取消授权；不受冷却限制 |
| `poweroff` | 先请求断锁，再拉低PWR_HOLD；未实际断电时仍保持软件关机锁定 |
| `reboot` | 先请求断锁，再重启；重启后仍有10秒冷却 |

K5 在本次开机后必须先松开，再长按至少3秒才触发关机，避免开机时一直按住导致自动关机。没有自动循环开锁命令。

当前交付固件已经启用 `CONFIG_SK_LOCK_OUTPUT_ENABLED=y` 和 `CONFIG_SK_LOCK_ACTIVE_LOW=y`，不需要再进menuconfig开放输出。启动应显示 `app=0.1.1-sk-test`、`[LOCK] ENABLED`，状态中的 `enabled=1`。如只测其他功能，可在 `idf.py menuconfig` → **SK board diagnostics** 关闭 `Enable lock output for bench testing`。有效极性需匹配电路；新增NPN驱动PMOS时通常为**高有效**，应关闭低有效选项。

## 一秒保护的具体含义

- 时间硬上限写死为1000ms，拒绝超限、负数、溢出、尾随垃圾；最短20ms。
- 先设置正在运行的1MHz GPTimer单次报警，再打开GPIO；报警设在请求时长前2ms，预留正常中断延迟余量。
- 报警ISR直接关GPIO，ISR及所用GPIO/定时器控制函数在IRAM；不依赖串口、ADC或主循环完成。
- 动作中重复请求不会延长脉冲。断电后至少10秒冷却，复位后也等待10秒；定时器/驱动错误锁死本次启动的动作功能。
- 动作期间测到ADC无效、低压或高压会提前请求断电；输出动作前、动作中采样最低值、动作后电池电压（没有采到时为-1）。20ms轮询不能捕获所有瞬态。
- **这仍是软件关断**：长时间屏蔽中断、芯片故障、MOS击穿或驱动硬件错误不能由此保证绝对1秒；看门狗是补充恢复机制。如果1秒是不可越过的物理上限，应另加独立硬件定时切断。线圈电流衰减也不等于GPIO关断瞬间，需要示波器/电流测量确认。

## 上板逐项验收

1. 先完成上面的电路检查，断开线圈，以限流电源/合适电池供电。记录万用表VBAT、3V3、USB5V；确认复位/下载/MCU断电时锁输出不供电。
2. 启动后核对板型、ESP-IDF版本、MAC、Flash=4MB、复位原因。观察D3闪3次，串口每秒有 `[ADC]`、`[KEY]`、`[LOCK]`、`[TEMP]`、`[SYS]`。
3. 用万用表分别对比VBAT及R4/R7中点；应满足中点约VBAT/2。比较日志与表读数，记录绝对误差，不能仅看 `IN_RANGE` 判断精度通过。
4. 按/松 K3、K4、BOOT，核对一次完整按压只增加一次计数。测K5松开/按下节点电压并核对事件；运行中的BOOT不应触发锁。按RESET确认重启。
5. 依次执行 `led on`、`led off`、`led test`，观察D3。充电灯D1由TP4054直接控制，插拔USB观察充电指示并测电池电压/充电电流，软件不能读取它。
6. 执行 `selftest`，确认NVS写入、读回、恢复/删除探针成功。此项不会自动擦除已有NVS；它不是整片Flash耐久/全地址测试。执行 `wifi`，有AP时观察RSSI，零AP不能单独判RF故障；BLE未做空口测试。
7. 当前固件已开放锁输出，建议**先用假负载+示波器**：开机等10秒 → `arm` → `pulse 100` → 断电后等10秒 → `arm` → `pulse 1000`；测有效电平/输出电流的持续时间及断电后的衰减。验证 `pulse 1001` 被拒、重复脉冲不续时、`off` 提前切断、复位默认断电。软件显示 `commanded_on=0` 不是锁反馈。
8. 确认线圈规格后接实际锁，从100ms开始，观察解锁与返回，测负载电池压降和线圈电流、温升；不要直接反复执行1秒。故意停止读取串口时，示波器仍须验证脉冲正常切断。
9. K5松开后长按3秒或执行 `poweroff`；用表测真实断电和关机电流。图中ADC_BAT一直接电池，需排查关机回灌；串口消失本身不能证明彻底断电。

软件不能测量没有接入ADC/传感器的3V3、USB5V、VLOCK实际电压、电流、锁舌位置和线圈温度。芯片内部温度不能替代线圈温度。

## 自动验证

```sh
python3 tests/run_host_tests.py
```

在有 `cc` 的Linux/WSL运行。覆盖显式禁用配置、两种极性下的最大时长、重复请求、冷却、提前停止、旧报警、定时器/读计数/GPIO错误，及解析、分压、阈值、去抖。使用生产 `lock_control.c`，模拟硬件；不会连接实板，也不能测真实中断延迟。构建及测试报告保存在本项目 `tmp/`。
